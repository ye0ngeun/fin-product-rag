## 1. 위키 후보 선별 오류 (F2003, F2004)

- **문제:** "중도상환수수료는 어떻게 계산돼?" 수집에서 프롬프트2가 회사 문서 "오션펀딩"은 고르고, 담보 인정 비율·모기지 론·한국주택금융공사·기준금리처럼 관련 있는 문서는 버렸습니다. 검색 후보에는 "루트비히 판 베토벤", "버니 샌더스", "전기자동차" 같은 문서도 섞였습니다. 고른 것이 없다는 빈 결과가 캐시에 남아, 프롬프트를 고쳐도 다시 수집되지 않았습니다.
- **원인:**
  - 위키 전문 검색은 본문 어딘가에 검색어가 스친 문서까지 돌려줍니다.
  - 프롬프트2에 "고를 문서 번호"만 받으니 판단 기준이 흔들렸습니다. 프롬프트에 "민간 회사는 빼라"고 적어도 모델이 회사 문서를 골랐습니다.
  - 중도상환수수료·고정금리는 한국어 위키에 같은 제목의 문서가 없습니다.
  - 캐시 키에 선별 규칙의 버전이 없었습니다.
- **해결:**
  - (PR #7) 검색어와 제목이 같은 문서(넘겨주기 포함)를 먼저 찾아 항상 남깁니다. 전문 검색 후보를 10개로 늘리고, 제목·요약에 검색어 글자가 없는 후보는 뺍니다. 캐시에 버전을 넣어 규칙이 바뀌면 다시 수집하고, `--reset-wiki` 를 추가했습니다.
  - (PR #8) 프롬프트2는 후보마다 **종류**(개념·제도·공공기관·기업·인물·기타)와 **관련 여부**만 판단합니다. 무엇을 남길지는 코드가 정합니다. 개념·제도·공공기관이면서 관련 있는 문서만 남깁니다.
  - 위키에 없는 용어는 위키에서 억지로 찾지 않고, 이미 색인한 용어사전이 근거가 됩니다.
- **결과:** 오션펀딩·뱅크몰 같은 회사 문서는 모델이 관련 있다고 해도 빠졌습니다. 고정금리·변동금리 검색어에서는 이자율·기준금리·한국은행 기준금리가 들어갔습니다. 실행 로그에는 후보마다 `이자율(개념·관련)`, `오션펀딩(기업)` 처럼 판단이 찍혀 버린 이유를 볼 수 있습니다. 관련 테스트는 `test_company_and_irrelevant_kinds_dropped_by_code` 와 `test_exact_title_always_kept_even_if_model_picks_none` 입니다.

## 2. 엉뚱한 근거 (F2006)

- **문제:** 상품을 고르지 않고 "LTV가 뭐야?"를 물으면 근거 1~3번이 상관없는 신용대출·저축은행 상품이었습니다. 사전 근거로는 "평가", "통신비", "해지율" 같은 낱말과 800선 126쪽(레그테크)이 들어왔습니다. 답변은 LTV 정의에 평택저축은행 상품을 인용했습니다.
- **원인:**
  - 관련도와 상관없이 Top-k를 그대로 썼습니다. 그래서 상품 컬렉션에서도 늘 3개가 들어왔습니다.
  - "LTV" 같은 짧은 약어는 임베딩 유사도가 낮아서, 정의 항목이 순위에서 밀렸습니다.
  - 주택금융공사 단어사전에는 "통신에 드는 비용"처럼 설명이 아주 짧은 일반 낱말이 많았습니다.
- **해결 (PR #10):**
  - 관련도 문턱(`min_relevance` 0.3, `relative_margin` 0.15)을 두었습니다. 상품을 고르지 않았을 때 상품 정보는 더 높은 문턱(`meta_min_relevance` 0.45)을 넘어야 들어갑니다.
  - 질문 용어와 제목이 같은 용어사전 항목을 먼저 넣습니다(`keyword_top_k` 2).
  - 설명이 20자 미만인 주택금융공사 항목은 색인하지 않습니다.
  - 프롬프트3에 "용어 질문에 특정 상품을 예로 끌어오지 않는다"를 넣었습니다.
  - `--show-evidence` 로 근거별 점수와 찾은 방식(용어 일치/유사도)을 보게 했습니다.
- **결과:** 상관없는 상품 근거가 사라지고 위키 "담보 인정 비율"이 0.55점으로 잡혔습니다. 남은 오매칭은 3번에서 고쳤습니다. 문턱 값은 이 점수(관련 위키 0.45~0.55)를 보고 정했습니다.

## 3. 용어 일치 오매칭과 없는 내용 인용 (F2006, F2007)

- **문제:** "용어 일치"로 들어온 근거 1·2번이 800선 목차(7쪽)와 상관없는 108쪽(노동비용)이었습니다. 답변은 "감정가 5억, LTV 80%면 4억" 같은 예시를 근거 2번으로 인용했지만, 근거 2번에는 그런 내용이 없었습니다.
- **원인:**
  - 약어 일치를 "본문에 `(LTV)` 가 있는 문서"로 찾았습니다. 800선은 한 쪽에 용어가 여러 개 있어서, 다른 용어 설명 속의 약어에도 걸렸습니다.
  - 목차 쪽은 용어 이름만 몰려 있어서 유사도가 높게 나왔습니다.
  - 프롬프트3이 "근거에 없는 예시·계산"을 막지 않았습니다.
- **해결 (PR #11):**
  - 약어 일치는 용어 1개가 문서 1개인 사전(주택금융공사·우체국 2종)에서, 첫 줄(용어 줄)에 약어가 있을 때만 찾습니다.
  - 800선에서 `용어 ···· 쪽번호` 줄이 많은 목차·찾아보기 쪽은 색인하지 않습니다.
  - 프롬프트3에 "근거에 없는 예시나 가상의 계산을 새로 만들지 않는다, 내용이 실제로 적힌 근거에만 번호를 붙인다"를 넣었습니다.
- **결과:** "LTV가 뭐야?"의 근거 5개가 모두 LTV 관련(위키 0.45~0.55점, 800선 408쪽)이 되었고 인용도 근거 내용과 맞았습니다. 이 결과로 F2006~F2008을 완료로 보았습니다. `loan_docs` 는 짧은 항목과 목차를 정리한 뒤 4,888청크입니다.

## 4. GMS 502 Bad Gateway (NF2001, NF2006)

- **문제:** `search_compare` 실행 중 임베딩 호출이 `502 Bad Gateway` 로 실패했고, 스크립트 전체가 멈췄습니다.
- **원인:** SSAFY GMS 게이트웨이의 일시 오류였습니다. 재시도가 기본 2회뿐이었고, 질문 하나가 실패하면 나머지 결과도 저장되지 않았습니다. MMR 질문 하나가 임베딩을 3~4번 불러서 오류를 만날 확률도 높았습니다.
- **해결 (PR #14):**
  - `llm.max_retries` 5, `timeout_sec` 60을 채팅 모델과 임베딩에 적용했습니다. OpenAI 클라이언트가 간격을 늘려 가며 다시 시도합니다.
  - 질문 임베딩을 `retrieve` 에서 한 번만 만들어 두 컬렉션 검색과 MMR이 같이 씁니다. 질문당 호출이 3번에서 1번으로 줄었습니다.
  - 검증 스크립트는 재시도 후에도 실패한 질문만 건너뛰고, 나머지 결과를 저장한 뒤 실패한 질문을 알려 줍니다.
- **결과:** 다시 실행했을 때 두 스크립트가 끝까지 돌았습니다. 검색 결과는 바뀌지 않았습니다.

## 5. MMR 근거 수 감소 (F2014)

- **문제:** MMR로 "LTV가 뭐야?"를 검색하면 근거가 5개가 아니라 2개였고, 주택금융공사 "위반" 같은 잡음이 들어왔습니다.
- **원인:** MMR이 문턱 밖의 후보까지 섞어 5개를 고른 뒤에 문턱을 적용했습니다. 그래서 고른 것 중 3개가 버려졌습니다.
- **해결 (PR #14):** 후보를 한 번 조회(임베딩 포함)한 뒤, 문턱을 통과한 후보 안에서만 `maximal_marginal_relevance` 로 k개를 고릅니다. `mmr_lambda` 는 관련도를 더 보도록 0.5에서 0.7로 바꿨습니다.
- **결과:** MMR도 근거를 5개씩 채우고, 유사도 검색과 다른 근거가 들어옵니다. 같은 위키 문서의 여러 청크가 근거에 몰리던 것도 줄었습니다(`search_compare.md`). 관련 테스트는 `test_mmr_picks_k_among_candidates_that_pass_threshold` 입니다.

## 6. "원리금균등상환" 근거 없음 (F2007, F2015) — 고치지 않고 한계로 기록

- **문제:** RAG 전후 비교 q5 "원리금균등상환이 뭐야?"에서 RAG 답변의 인용 근거가 0개였고, 자동 점검은 틀림이었습니다.
- **원인:** 제목이 같은 사전 항목이 없었습니다.
- **해결 시도 (PR #14):** 4글자 이상 한글 용어는 제목이 비슷한 항목도 찾게 했습니다. 2글자 단위 겹침이 0.6 이상이면 같은 용어로 봅니다(예: 원리금균등상환 → 원리금균등분할상환, 0.71). 그래도 근거가 잡히지 않아, 색인한 위키·사전에 해당 항목이 없다고 판단했습니다.
- **결정 (PR #15):** 더 고치지 않고 "근거 문서 부재 시 한계" 사례로 기록했습니다. 근거가 없을 때 모델이 지어내지 않고 "확인되지 않습니다"라고 답한 것은 의도한 동작입니다. `config/eval_questions.yaml` 의 `note` 가 `rag_compare.md` 의 q5 아래에 "참고(한계)"로 들어갑니다. 해당 용어 문서를 추가로 색인하면 개선할 수 있습니다.
- **결과:** RAG 자동 점검은 5/6, RAG 없이는 3/6입니다.
