설정 값은 모두 [`config/settings.yaml`](../config/settings.yaml), 프롬프트는 [`src/rag/prompts.py`](../src/rag/prompts.py) 에 있습니다.

## 1. 전체 흐름

```
[수집]                         [색인]                         [질문]
금감원 API ─ fss_collector ──▶ fss_loader ─▶ loan_meta (상품 1건 = 청크 1개)
                                                         │
용어사전 CSV·800선 PDF ─ glossary_loader ─▶ loan_docs ◀──┤ retrieve: 두 컬렉션 검색·병합·중복 제거
위키백과 ─ 프롬프트1 검색어 ─ 위키 검색 ─ 프롬프트2 선별 ─ 본문 수집(캐시) ─▶ loan_docs
                                                         ▼
                                    generate: 프롬프트3 → [근거 n] 인용 답변 → 인용된 근거만 출처 표시
```

LangGraph 그래프는 `retrieve` → `generate` 두 노드입니다 ([`src/rag/graph.py`](../src/rag/graph.py)). 위키 수집은 길잡이에서 질문할 때 그래프 앞에서 실행되고(캐시가 있으면 건너뜀), 그래프는 색인된 근거만 다룹니다.

## 2. 컬렉션 구조와 메타데이터 (2.3)

두 컬렉션 모두 Chroma, 코사인 거리(`hnsw:space=cosine`), 임베딩 `text-embedding-3-small`(GMS).

### `loan_meta` — 금감원 대출상품 (285건)

| 항목 | 내용 |
| :--- | :--- |
| 단위 | 상품 1건 = 청크 1개 (청킹하지 않음) |
| 청크 ID | `{loan_type}:{fin_co_no}:{fin_prdt_cd}` (예: `mortgage:0010001:1054`). 고정 ID라 재색인은 덮어쓰기, 원본에서 사라진 상품은 같은 유형 안에서 삭제 |
| 텍스트 (2.2) | 금융회사·권역, 상품명, 대출 유형, 담보 유형·상환 방식·금리 유형, 금리 요약(최저/최고/평균), 옵션별 금리(신용대출은 신용점수 구간별), 대출 한도, 중도상환 수수료, 연체 이자율, 부대비용, 가입 방법, 공시 기간 |
| 메타데이터 | `product_id`, `loan_type`, `loan_type_nm`, `fin_co_no`, `fin_prdt_cd`, `kor_co_nm`, `fin_prdt_nm`, `fin_grp_nm`, `rate_min`, `rate_max`, `rate_avg`(숫자), `rate_types`, `rpay_types`, `mrtg_types`, `option_count`, `dcls_month`, `dcls_strt_day`, `dcls_end_day`, `collected_at`, `title`, `source`, `source_url` |

텍스트 구성 이유: 사용자는 "금리 4% 이하 고정금리", "중도상환수수료 없는", "비대면 가입" 처럼 금리·상환·수수료·가입 방법으로 상품을 찾습니다. 그래서 공시 항목을 빠짐없이 텍스트에 넣고, 숫자 조건(금리)과 범주 조건(유형·권역·상환방식)은 메타데이터로도 넣어 코드가 정확히 거르게 했습니다.

### `loan_docs` — 외부 문서 (약 4,900청크)

| 출처 (`doc_type`) | 단위 | 청크 수(영은 PC) | 원문 위치 메타데이터 |
| :--- | :--- | ---: | :--- |
| 위키백과 (`wiki`) | 문서 1개 → 1,000자 청크 | 69 | `source_url`(문서 URL), `license`, `query`(검색어) |
| 주택금융공사 단어사전 (`glossary_hf`) | 용어 1개 = 문서 1개 (설명 20자 미만 제외) | 1,821 | `source_url`(데이터 페이지), `source_file` |
| 우체국예금보험 금융용어사전 (`glossary_epost`) | 용어 1개 = 문서 1개 | 1,197 | 같음 |
| 우체국 챗봇 금융용어 사전 (`glossary_epost_chatbot`) | 용어 1개 = 문서 1개 | 1,038 | 같음 |
| 한은 경제금융용어 800선 (`glossary_bok`) | PDF 1쪽 = 문서 1개 (목차·빈 쪽 제외) | 763 | `source_file`, `page` |

- 공통 메타데이터: `product_id`, `doc_type`, `doc_id`, `chunk_seq`, `title`, `source`, `source_url`.
- 청크 ID: `{product_id}:{doc_id}:{순번}` (예: `common:wiki-12345:0`, `common:hf-W0001:0`, `common:bok800-p408:0`).
- `product_id`: 위키·용어사전은 특정 상품이 아니라 모든 상품이 같이 쓰는 개념 문서라 `common`. 상품을 고르면 검색 범위를 `common` + 그 상품으로 좁히는 필터로 씁니다. (금감원 외에 상품별 설명서는 수집하지 않았습니다.)

## 3. 문서 수집·청킹·색인 순서 (F2003~F2005)

1. **용어사전·PDF** (`index_docs --glossary`): `data/raw/docs/` 의 파일을 `settings.yaml` 의 `docs` 패턴으로 찾아 읽습니다(CSV는 UTF-8/CP949 자동). 용어 1개를 `용어 (영문)\n설명` 텍스트로, PDF는 쪽마다 텍스트로 만든 뒤 청킹합니다.
2. **위키백과** (질문 때, 또는 `index_docs --product ID --question ...`, `--seed N`):
   1. 프롬프트1이 상품 정보와 질문에서 검색어를 최대 4개 뽑습니다. 상품의 대출 유형은 항상 포함.
   2. 이미 수집한 검색어면 캐시(`wiki_cache.json`)를 보고 건너뜁니다 (NF2002).
   3. 검색어와 제목이 같은 문서(넘겨주기 포함)를 먼저 찾고, 전문 검색 10개 중 제목·요약에 검색어 글자가 있는 것을 후보로 더합니다.
   4. 프롬프트2가 후보마다 종류와 관련 여부를 판단하고, 코드가 개념·제도·공공기관이면서 관련 있는 문서를 검색어당 최대 2개 고릅니다. 제목 일치 문서는 항상 남깁니다.
   5. 고른 문서만 본문을 받아(200자 미만 제외) 청킹·색인하고 캐시에 기록합니다.
3. **청킹**: `RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=200)`. 용어사전 항목은 대부분 1,000자보다 짧아 그대로 1청크가 됩니다.
4. **색인**: 고정 청크 ID로 덮어쓰기(upsert)라 다시 실행해도 청크 수가 늘지 않고, 같은 출처 종류에서 이번에 없는 청크는 지웁니다.

### 출처 종류별로 청킹 단위를 다르게 한 이유 (F2016)

- 용어사전 CSV는 행 하나가 완결된 정의라서 용어 1개 = 문서 1개로 두었습니다. 여러 용어를 이어 붙여 자르면 한 청크에 상관없는 용어가 섞여 검색이 흐려집니다.
- 800선 PDF는 한 쪽에 용어 1~2개가 들어가는 구성이라 쪽 단위로 두고, 출처를 쪽 번호로 표시합니다. 목차·찾아보기 쪽은 용어 이름만 늘어놓아 검색을 흐려서 뺐습니다.
- 위키 문서는 길어서 1,000자 청크로 나눕니다.

## 4. 프롬프트 (2.4)

| 프롬프트 | 역할 | 입력 | 출력 형식 |
| :--- | :--- | :--- | :--- |
| 1 검색어 추출 (F2003) | 대출 전문가 역할로 위키 문서 제목이 될 짧은 명사구 고르기. 상품명·숫자 금지, 대출 유형 1개 필수 | 질문, 상품 텍스트 | JSON 문자열 배열 `["주택담보대출", "담보인정비율"]` |
| 2 후보 선별 (F2004) | 본문을 받기 전에 제목·요약만 보고 후보마다 종류(개념·제도·공공기관·기업·인물·기타)와 관련 여부 판단 | 질문, 상품, 검색어, 후보 목록 | JSON 배열 `[{"no": 3, "kind": "개념", "relevant": true}]` |
| 3 답변 생성 (F2007) | 근거만 사용, 문장마다 `[근거 n]`, 숫자는 그대로, 근거 없으면 "제공된 문서에서 확인되지 않습니다.", 가입 권유·개인 판단 금지 | 이전 대화, 질문, 번호 붙은 근거 | 인용 번호가 붙은 한국어 답변 |

서비스용 프롬프트도 두 개 더 있습니다: 프롬프트4 조건 해석(자연어 조건 → `loan_type`, `rate_max`, `rate_type`, `rpay_type`, `fin_grp`, `company`, `query` JSON), 프롬프트5 조건 맞는 상품 고르기(JSON 배열). 비교용 `BASELINE_PROMPT` 는 근거 없이 질문만 줍니다(F2015).

프롬프트2를 "고를 문서 번호"가 아니라 "종류·관련 여부 판단"으로 바꾼 이유: 처음에는 모델이 대출 중개 플랫폼·핀테크 기업 문서를 관련 있다고 골랐습니다. 판단(LLM)과 규칙(코드: 개념·제도·공공기관만)을 나누니 기업·인물 문서가 안정적으로 걸러졌습니다.

## 5. 검색 결과 병합과 중복 제거 (F2006)

`retrieve` 노드([`src/rag/retriever.py`](../src/rag/retriever.py))가 아래 순서로 근거를 모으고 `[근거 n]` 번호를 붙입니다.

1. **상품 정보**: 상품을 골랐으면 그 상품의 `loan_meta` 청크를 근거 1번으로 넣습니다. 고르지 않았으면 `loan_meta` 에서 관련도 0.45 이상인 상품을 최대 3개 넣습니다.
2. **용어 일치**: 질문의 용어(LTV, 담보인정비율 등)와 제목이 같은 용어사전 항목을 최대 2개 먼저 넣습니다. 약어는 단문 사전 첫 줄의 `(LTV)` 로, 4글자 이상 한글 용어는 비슷한 제목(2글자 단위 겹침 0.6 이상)으로도 찾습니다.
3. **유사도/MMR 검색**: `loan_docs` 에서 Top-k 5개. 상품을 골랐으면 `product_id ∈ {common, 그 상품}` 필터.
4. **문턱**: 관련도 0.3 미만, 또는 1등보다 0.15 이상 낮은 근거는 버립니다.
5. **중복 제거**: 같은 청크 ID, 또는 공백을 정리한 본문이 같은 청크(여러 사전에 같은 설명)는 처음 것만 남깁니다.

질문 임베딩은 한 번만 만들어 두 컬렉션과 MMR이 같이 씁니다.

## 6. 검색 설정 값과 이유 (2.5)

| 설정 | 값 | 이유 | 바꿨을 때 |
| :--- | :--- | :--- | :--- |
| `chunk_size` | 1000 | 위키 문단 2~3개 분량. 용어사전 항목은 대부분 이보다 짧아 1청크 유지 | 줄이면 위키 청크 수가 늘고 한 청크의 맥락이 짧아짐. 용어사전은 거의 변화 없음 |
| `chunk_overlap` | 200 | 문단 경계에서 잘린 문장을 앞뒤 청크가 함께 갖도록 | 0이면 경계 문장이 잘려 검색이 빗나갈 수 있음 |
| `top_k` | 5 | 상품 정보 1 + 용어 일치 최대 2 + 문서 5로, 프롬프트에 넣기 적당한 분량 | 3이면 근거가 짧아지고, 10이면 관련 낮은 청크가 끼어 문턱에서 대부분 걸러짐 |
| `meta_top_k` | 3 | 상품을 고르지 않은 질문에서 관련 상품 후보 | — |
| `min_relevance` / `meta_min_relevance` | 0.3 / 0.45 | `--show-evidence` 실측: LTV 질문의 관련 위키 0.45~0.55, 상관없는 상품은 0.45 미만 | 낮추면 상관없는 근거, 높이면 근거 0개 질문이 늘어남 |
| `relative_margin` | 0.15 | 1등보다 크게 낮은 근거 제거 | 비우면 문턱만 적용 |
| `keyword_top_k` | 2 | 약어·용어 질문에서 정의 항목이 유사도 순위에 밀리지 않게 | 0이면 "LTV" 같은 약어 질문의 정의가 빠질 수 있음 |
| `search_type` | similarity | 기본. MMR은 F2014 비교·선택용 | mmr: 후보 20개 중 λ=0.7로 다양하게 |

값을 바꾼 결과는 [검증 결과](03_검증결과.md) 4.2·4.3에 기록합니다.

## 7. 근거 표시 방식 (F2008)

- 답변 본문에서 `[근거 1]`, `[근거 1][근거 3]`, `[근거 1, 3]` 표기를 읽어 **인용된 번호의 근거만** 출처로 보여 줍니다.
- 출처 한 줄: `[근거 n] 출처 종류 · 제목 — 원문 위치`. 원문 위치는 위키 URL, 사전 데이터 페이지, PDF 파일명·쪽, 금감원 상품정보는 수집일까지 붙입니다. 출처 종류(금감원 상품정보 / 위키백과 / 각 사전 / 800선)로 메타데이터와 외부 문서가 구분됩니다 (F2016).
- 인용이 없으면 "답변에 인용된 근거가 없습니다."를 표시합니다.
- 화면에서는 근거를 펼쳐 원문을 볼 수 있습니다.

## 8. 서비스 기능과 화면 (2.6, F2009~F2012)

| 화면 | 기능 |
| :--- | :--- |
| 사이드바 | 시작 스탯(현금자산·비상금·월 소득·생활비·기존 상환·월 여유 목표), 상품 고르기, 색인 현황, 면책·출처 |
| 대출 계획 | 집값·대출금·기간·상환방식·적용 금리(공시 최저/평균/최고) → 첫 달 상환액, 총이자, 월 남는 돈, 집의 불빛, 구별 실거래 사례 |
| 상품 찾기·비교 | 자연어 조건 탐색 → 상품 카드(맞은 조건 표시), 2~3개 비교표(공시값 그대로), 상품별 월 상환액, 근거를 붙인 차이 요약 |
| 한 달 살아보기 | 월급 → 생활비 → 기존 상환 → 새 상환 → 남은 돈 |
| 길잡이 | 고른 상품과의 대화(상품마다 기록 분리), 진행 상태 표시, 인용 근거 펼치기 |

### 도메인 특화 기능을 이렇게 설계한 이유 (F2010)

- 대출 상품 정보에서 사용자가 실제로 궁금한 것은 "이 금리면 매달 얼마고, 그래도 생활이 되나"입니다. 그래서 금리 설명에 그치지 않고 공시 금리로 월 상환액과 월 남는 돈을 계산해 집 불빛으로 보여 줍니다.
- 금융 숫자를 LLM이 만들면 틀릴 위험이 커서, **금리·상환액·비교표는 코드가 공시값으로 계산**하고 LLM은 용어 설명과 차이 요약만 근거와 함께 씁니다. 계산에 쓴 금리는 그 상품의 공시 근거로 보여 줍니다.
- 취득세·중개보수와 제도상 LTV·DSR 한도는 반영하지 않으며 화면에 그렇게 적습니다.

### 조건 기반 탐색 (F2011)

1. 프롬프트4가 자연어 조건을 검색 조건 JSON으로 바꿉니다.
2. 금리 상한·대출 유형·금리 유형·상환방식·권역·회사는 **코드가 메타데이터로 판정**해 조건과 맞지 않는 상품이 섞이지 않게 합니다.
3. 나머지 조건(`query`, 예: 비대면 가입)은 남은 후보를 유사도로 좁힌 뒤 프롬프트5가 공시 텍스트만 보고 판단합니다.
4. 0건이면 어느 조건에서 후보가 사라졌는지 알려 줍니다.

### 화면 안내 (F2012)

수집·검색·답변 작성 중 진행 상태(`st.status`), 색인 없음·API 키 없음 안내(실행할 명령 표시), 검색 결과 없음 안내, 오류는 안내 문구만(NF2004), 화면 하단과 답변 아래에 면책·금감원 출처 문구.

## 9. 선택 이유, 겪은 문제와 해결

| 문제 | 원인 | 해결 |
| :--- | :--- | :--- |
| 위키 후보에 기업·인물·목록 문서가 섞임 | 전문 검색 결과에 검색어가 본문에만 스친 문서가 많음 | 제목 일치 문서 우선, 제목·요약에 검색어 글자가 있는 후보만, 프롬프트2를 종류 판단으로 바꾸고 코드가 거름 |
| 위키에 없는 용어(중도상환수수료 등) | 위키 문서 부재 | 용어사전 4종을 함께 색인해 근거로 사용 (F2016) |
| 용어 질문에 상관없는 상품·짧은 사전 항목이 근거로 끼어 답이 흐려짐 | 문턱 없이 Top-k를 그대로 사용, "통신에 드는 비용" 같은 짧은 설명 | 관련도 문턱·상대 문턱, 메타는 더 높은 문턱, 설명 20자 미만 항목 제외 |
| "LTV" 질문의 정의가 유사도 순위에서 밀림 | 짧은 약어는 임베딩 유사도가 낮음 | 용어 일치 검색(제목·약어) 추가 |
| 약어 일치가 800선 엉뚱한 쪽을 잡음 | 한 쪽에 용어 여러 개, 본문 어딘가의 약어에 걸림 | 약어 일치는 단문 사전의 첫 줄에서만 |
| 800선 목차 쪽이 근거로 뽑힘 | 용어 이름이 몰려 있어 유사도가 높음 | 목차 쪽 판별 후 색인 제외 |
| 답변이 근거에 없는 예시·계산을 만들어 인용을 붙임 | 프롬프트 제약 부족 | 프롬프트3에 "근거에 없는 예시·계산 금지", 용어 질문에 상품 예시 금지 |
| GMS 502·시간 초과 | 게이트웨이 일시 오류 | 재시도 5회·타임아웃 60초, 질문 임베딩 1회로 호출 수 감소, 검증 스크립트는 실패 질문만 건너뜀 |
| MMR이 문턱 밖 문서를 골라 근거가 줄어듦 | MMR 후 문턱 적용 | 문턱 통과 후보 안에서 MMR |
| "원리금균등상환" 질문 근거 0개 | 색인한 문서에 해당 항목 없음 | 비슷한 제목 찾기를 추가했으나 여전히 없음 → 지어내지 않고 "확인되지 않습니다"로 답하는 한계 사례로 기록 |

컬렉션을 상품 정보와 외부 문서 둘로 나눈 이유: 상품 정보는 정확한 공시값을 그대로 근거 1번에 넣어야 하고(필터·ID 조회), 외부 문서는 개념 설명이라 유사도 검색이 맞습니다. 둘을 섞으면 용어 질문에 상관없는 상품이 끼고, 상품 질문에 상품 정보가 순위에서 밀립니다.
